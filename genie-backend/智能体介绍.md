# Genie Backend 智能体系统设计文档

## 1. 系统概述

Genie Backend 是一个基于多智能体协作的任务处理系统，采用 ReAct（Reasoning + Acting）模式，支持任务规划、执行和总结的完整工作流。系统通过智能体之间的协作和工具调用来完成复杂的任务。

## 2. 核心智能体架构

### 2.1 智能体类层次结构

```
BaseAgent (抽象基类)
    ├── ReActAgent (ReAct模式抽象基类)
    │   ├── PlanningAgent (规划智能体)
    │   ├── ExecutorAgent (执行智能体)
    │   └── ReactImplAgent (单步ReAct智能体)
    └── SummaryAgent (总结智能体)
```

### 2.2 智能体详细介绍

#### 2.2.1 BaseAgent - 智能体基类

**位置**: `com.jd.genie.agent.agent.BaseAgent`

**职责**:
- 管理智能体的基本属性（名称、描述、系统提示词）
- 维护智能体的记忆（Memory）和工具集合（ToolCollection）
- 控制智能体的执行流程（状态管理、步数限制）
- 提供通用的运行循环（run方法）

**核心属性**:
- `name`: 智能体名称
- `description`: 智能体描述
- `systemPrompt`: 系统提示词
- `nextStepPrompt`: 下一步提示词
- `availableTools`: 可用工具集合
- `memory`: 对话历史记忆
- `llm`: 大语言模型实例
- `state`: 智能体状态（IDLE/RUNNING/FINISHED/ERROR）
- `maxSteps`: 最大步数限制
- `currentStep`: 当前步数

**核心方法**:
- `run(String query)`: 运行智能体主循环
- `step()`: 执行单个步骤（抽象方法，由子类实现）
- `updateMemory()`: 更新记忆

---

#### 2.2.2 ReActAgent - ReAct模式基类

**位置**: `com.jd.genie.agent.agent.ReActAgent`

**职责**:
- 实现 ReAct（Reasoning + Acting）模式
- 提供思考-行动的执行框架
- 支持数字员工（Digital Employee）功能

**ReAct模式**:
```
Think (思考) → Act (行动) → Observe (观察) → Think → ...
```

**核心方法**:
- `think()`: 思考过程（抽象方法）
- `act()`: 执行行动（抽象方法）
- `step()`: 完整的思考-行动循环
- `generateDigitalEmployee()`: 生成数字员工

---

#### 2.2.3 PlanningAgent - 规划智能体

**位置**: `com.jd.genie.agent.agent.PlanningAgent`

**职责**:
- 将用户的复杂任务拆解为多个子任务
- 管理任务计划的创建、更新和跟踪
- 判断任务是否完成

**工作流程**:
1. 接收用户的原始任务
2. 分析任务复杂度和需求
3. 调用 PlanningTool 创建任务计划
4. 返回任务列表（通过 `<sep>` 分隔）
5. 根据执行结果更新任务状态
6. 当所有子任务完成时返回 "finish"

**使用场景**:
- Plan-Solve 模式（`AgentType.PLAN_SOLVE`）
- 复杂任务的分步执行

**关键特性**:
- 支持任务状态管理（not_started/in_progress/completed/blocked）
- 支持 SOP（标准操作流程）提示词注入
- 支持文件信息上下文

---

#### 2.2.4 ExecutorAgent - 执行智能体

**位置**: `com.jd.genie.agent.agent.ExecutorAgent`

**职责**:
- 执行具体的任务（由 PlanningAgent 分配）
- 调用各种工具完成任务
- 管理任务执行过程中的记忆和状态

**工作流程**:
1. 接收单个任务描述
2. 思考：分析任务需求，确定需要使用的工具
3. 行动：调用相应的工具执行任务
4. 观察：收集工具返回结果
5. 重复 2-4 直到任务完成

**使用场景**:
- Plan-Solve 模式中的子任务执行
- 支持并行执行多个子任务

**关键特性**:
- 支持数字员工功能（动态工具别名）
- 支持多轮工具调用
- 支持观察结果截断（maxObserve）
- 支持 SOP 提示词

---

#### 2.2.5 ReactImplAgent - 单步ReAct智能体

**位置**: `com.jd.genie.agent.agent.ReactImplAgent`

**职责**:
- 提供简化的 ReAct 执行流程
- 直接处理用户任务，无需任务拆解
- 适用于单步或少步任务

**工作流程**:
1. 接收用户任务
2. 思考并调用工具
3. 观察结果
4. 持续迭代直到完成

**使用场景**:
- ReAct 模式（`AgentType.REACT`）
- 简单任务的快速处理

**与 ExecutorAgent 的区别**:
- ReactImplAgent 直接接收用户任务
- ExecutorAgent 接收由 PlanningAgent 拆解的子任务

---

#### 2.2.6 SummaryAgent - 总结智能体

**位置**: `com.jd.genie.agent.agent.SummaryAgent`

**职责**:
- 总结任务执行过程
- 提取关键结果和文件
- 生成用户友好的任务摘要

**工作流程**:
1. 接收完整的对话历史（memory）
2. 分析任务执行过程
3. 提取关键信息和生成的文件
4. 生成结构化的总结

**输出格式**:
```
任务摘要 $$$ 文件名1、文件名2、文件名3
```

**关键特性**:
- 智能筛选文件（过滤内部临时文件）
- 支持消息长度限制
- 按重要性排序结果文件

---

## 3. 智能体协作模式

### 3.1 Plan-Solve 模式（多智能体协作）

**处理器**: `PlanSolveHandlerImpl`

**工作流程**:
```
用户任务
    ↓
PlanningAgent (任务拆解)
    ↓
子任务1, 子任务2, 子任务3, ...
    ↓
ExecutorAgent (并行/串行执行)
    ↓
执行结果
    ↓
PlanningAgent (更新计划/判断完成)
    ↓
循环直到所有任务完成
    ↓
SummaryAgent (总结)
    ↓
最终结果
```

**特点**:
- 支持复杂任务的分步执行
- 支持任务并行执行（多个 ExecutorAgent）
- 支持动态任务调整
- 适合多步骤、多维度的任务

**示例场景**:
- 数据分析：收集数据 → 数据处理 → 生成报告
- 市场调研：搜索信息 → 分析竞品 → 生成结论

---

### 3.2 ReAct 模式（单智能体）

**处理器**: `ReactHandlerImpl`

**工作流程**:
```
用户任务
    ↓
ReactImplAgent (思考-行动循环)
    ↓
最终结果
    ↓
SummaryAgent (总结)
    ↓
返回用户
```

**特点**:
- 流程简单，响应快速
- 单一智能体完成所有工作
- 适合简单或中等复杂度任务

**示例场景**:
- 信息检索
- 文件操作
- 简单问答

## 4. 工具系统

### 4.1 工具接口

**位置**: `com.jd.genie.agent.tool.BaseTool`

**接口定义**:
```java
public interface BaseTool {
    String getName();           // 工具名称
    String getDescription();    // 工具描述
    Map<String, Object> toParams();  // 工具参数定义
    Object execute(Object input);    // 执行工具
}
```

### 4.2 核心工具

#### 4.2.1 PlanningTool - 任务规划工具
- **功能**: 创建和管理任务计划
- **命令**: create, mark_step, finish
- **使用者**: PlanningAgent

#### 4.2.2 CodeInterpreterTool - 代码执行工具
- **功能**: 执行 Python 代码完成数据处理、分析
- **名称**: `python_executor` (已修改，避免与 DashScope 保留字冲突)
- **使用场景**: 数据处理、图表生成、复杂计算

#### 4.2.3 DeepSearchTool - 深度搜索工具
- **功能**: 搜索内外网知识
- **使用场景**: 信息检索、市场调研

#### 4.2.4 FileTool - 文件工具
- **功能**: 文件上传和下载
- **命令**: upload, get
- **使用场景**: 保存中间结果、读取上传文件

#### 4.2.5 ReportTool - 报告生成工具
- **功能**: 生成 HTML、Markdown、PPT 报告
- **使用场景**: 最终结果展示

#### 4.2.6 DataAnalysisTool - 数据分析工具
- **功能**: 查询和分析结构化数据
- **使用场景**: 数据库查询、数据分析

#### 4.2.7 McpTool - MCP协议工具
- **功能**: 支持 MCP（Model Context Protocol）工具集成
- **使用场景**: 扩展第三方工具

---

### 4.3 工具集合管理

**位置**: `com.jd.genie.agent.tool.ToolCollection`

**功能**:
- 管理智能体可用的工具集合
- 支持动态添加/移除工具

## 6. 关键设计模式

### 6.1 责任链模式
- `AgentHandlerFactory` 根据 `AgentType` 选择对应的处理器
- `PlanSolveHandlerImpl` 或 `ReactHandlerImpl` 处理请求

### 6.2 策略模式
- 不同的智能体类型对应不同的执行策略
- Plan-Solve 模式 vs ReAct 模式

### 6.3 观察者模式
- `Printer` 作为消息发布器
- 支持流式输出和事件通知

### 6.4 工厂模式
- `LLM` 类创建
- `Agent` 实例化

---

## 7. 执行流程示例

### 示例：用户提交"分析京东、淘宝、拼多多的优劣势"

#### Plan-Solve 模式执行流程：

1. **PlanningAgent 拆解任务**:
   ```
   任务1: 搜索京东的优劣势
   任务2: 搜索淘宝的优劣势
   任务3: 搜索拼多多的优劣势
   任务4: 生成综合分析报告
   ```

2. **ExecutorAgent 并行执行任务1-3**:
   - ExecutorAgent1 → DeepSearchTool("京东优劣势") → 保存结果
   - ExecutorAgent2 → DeepSearchTool("淘宝优劣势") → 保存结果
   - ExecutorAgent3 → DeepSearchTool("拼多多优劣势") → 保存结果

3. **ExecutorAgent 执行任务4**:
   - 读取前面的搜索结果
   - ReportTool 生成 HTML 报告

4. **PlanningAgent 判断完成**:
   - 返回 "finish"

5. **SummaryAgent 总结**:
   - 生成任务摘要
   - 提取报告文件
   - 返回用户

## 8. 配置与扩展

### 8.1 配置项（application.yml）

```yaml
autobots:
  autoagent:
    planner:
      model_name: gpt-4.1
      max_steps: 40
      system_prompt: {...}
    executor:
      model_name: gpt-4.1
      max_steps: 40
    react:
      model_name: gpt-4.1
      max_steps: 40
```

### 8.2 智能体类型

```java
public enum AgentType {
    COMPREHENSIVE(1),  // 综合模式
    WORKFLOW(2),       // 工作流模式
    PLAN_SOLVE(3),     // 规划求解模式
    ROUTER(4),         // 路由模式
    REACT(5);          // ReAct模式
}
```

### 8.3 扩展新工具

1. 实现 `BaseTool` 接口
2. 在 `ToolCollection` 中注册工具
3. 在配置文件中添加工具描述和参数

### 8.4 扩展新智能体

1. 继承 `BaseAgent` 或 `ReActAgent`
2. 实现 `step()` 或 `think()/act()` 方法
3. 创建对应的 Handler 实现 `AgentHandlerService`
4. 在 `AgentHandlerFactory` 中注册

## 9. 关键技术点

### 9.1 记忆管理
- 使用 `Memory` 类管理对话历史
- 支持消息角色：USER/ASSISTANT/SYSTEM/TOOL
- 支持消息截断和压缩

### 9.2 并发执行
- 使用 `CountDownLatch` 实现任务并行
- 每个并行任务使用独立的 ExecutorAgent 实例
- 任务完成后合并记忆和状态

### 9.3 流式输出
- 支持 SSE（Server-Sent Events）流式传输
- 实时推送思考过程和工具调用结果
- 提升用户体验

### 9.4 错误处理
- 智能体状态管理（IDLE/RUNNING/FINISHED/ERROR）
- 最大步数限制防止死循环
- 工具调用失败重试机制

### 9.5 数字员工
- 根据任务动态生成工具别名
- 提升用户理解体验
- 例如：file_tool → "数据记录员"

## 10. 注意事项

### 10.1 LLM API 兼容性
- 工具名称不能使用 `code_interpreter`（DashScope 保留字）
- 已改为 `python_executor`
- 需要注意不同 LLM 提供商的限制

### 10.2 性能优化
- 合理设置 `maxSteps` 避免过度迭代
- 使用 `maxObserve` 限制工具返回内容长度
- 过滤内部临时文件减少输出

### 10.3 Prompt 工程
- 系统提示词支持模板变量替换
- 支持 SOP（标准操作流程）注入
- 支持多语言提示词（通过配置Map）

## 12. 总结

Genie Backend 智能体系统通过**分层架构**和**多智能体协作**实现了复杂任务的自动化处理：

- **BaseAgent** 提供基础能力
- **ReActAgent** 实现思考-行动模式
- **PlanningAgent** 负责任务拆解
- **ExecutorAgent** 负责任务执行
- **ReactImplAgent** 提供简化流程
- **SummaryAgent** 负责结果总结

系统支持两种核心工作模式：
- **Plan-Solve 模式**：适合复杂多步任务
- **ReAct 模式**：适合简单快速任务

通过丰富的**工具系统**和灵活的**配置机制**，系统可以轻松扩展以支持更多场景。
